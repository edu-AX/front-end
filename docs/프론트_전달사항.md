# 프론트 담당에게 — 백엔드와 맞출 것

백엔드(데이터·계산 로직·API)는 이 프로젝트에 다 들어 있고, 테스트도 끝났어요. **이 프로젝트 위에 화면을 만들어 주세요.**
(`app/page.tsx`, `app/layout.tsx`는 자리만 잡아 둔 거라 지우고 새로 만들면 돼요.)

**백엔드 상태 (2026-11-13 기준)**
- 자동 테스트 49개 통과, 타입 체크·빌드 통과
- 실제 Gemini로 시나리오 질문 확인 완료 — 답변 1~2초
- 스택: Next.js 16 (App Router) + React 19 + TypeScript

## 0. 시작하는 법

1. Node.js 22 이상을 설치해요 ([nodejs.org](https://nodejs.org) LTS).
2. 프로젝트를 받은 뒤 폴더에서 `npm install`을 실행해요.
3. `.env.example`을 복사해 `.env.local`을 만들고 **`DEMO_MODE=true`**로 두세요.
   - API 키 없이도 챗봇이 고정 답 4개로 동작해요(동의율, 안전요원, 면책, 학생부 글자 수).
   - **API 키는 공유하지 않아요.** 실제 AI 답변 확인은 백엔드 PC나 배포 사이트에서 해요.
4. `npm run dev` → http://localhost:3000
5. `npm test`로 백엔드 로직이 깨지지 않았는지 확인할 수 있어요.

```
data/            ← 샘플 JSON 4개 (행사, 단계 템플릿, 지침, 변경 알림)
lib/types.ts     ← 공통 타입 = 우리 둘의 약속. 바꾸려면 서로 먼저 말하기
lib/schedule.ts  ← D-day 역산 (행사 카드 체크리스트)
lib/dashboard.ts ← 대시보드 위젯·캘린더에 들어갈 값
lib/upload/draft.ts ← 업로드 초안 → 행사 카드 변환
app/api/...      ← 챗봇·업로드 API (서버)
```

Tailwind는 아직 안 깔려 있어요. 프로젝트 폴더에서 아래 명령을 실행한 뒤 [Next.js 공식 안내](https://tailwindcss.com/docs/installation/framework-guides/nextjs)대로 `postcss.config.mjs`와 `globals.css`를 추가하면 돼요.

```bash
npm install tailwindcss @tailwindcss/postcss postcss
```

Framer Motion은 `npm install framer-motion`으로 설치해요.

## 1. 꼭 맞춰야 하는 약속 7가지

| # | 약속 | 내용 |
|---|---|---|
| 1 | **단계 id** | `plan`, `consent`, `vendor`, `safety_staff`, `safety_edu`, `execute`, `report`, `record` 8개. 화면에 보여줄 글자는 `label`을 쓰세요. |
| 2 | **변경 알림의 행사 연결** | 기획서에는 `eventId`가 하나였지만, 한 변경이 여러 행사에 걸려서 **`eventIds` 배열**로 바꿨어요. `stepId`가 `null`이면 특정 단계가 아니라 행사 카드 전체에 ⚠를 붙여요. |
| 3 | **localStorage** | 키는 `"handover:v1"` 하나, 모양은 `ClientState`(lib/types.ts)예요. 체크, 행사일 변경, 메모, "확인함", 업로드로 만든 카드가 전부 여기 들어가요. |
| 4 | **오늘 날짜** | `new Date()` 대신 `today()`(lib/dates.ts)를 쓰세요. 데모용 날짜(`2027-03-11`)를 넣어 두면 "수학여행 D-62"가 항상 똑같이 나와요. |
| 5 | **날짜 형식** | 모든 날짜는 `"YYYY-MM-DD"` 문자열이에요. D-day 글자는 `formatDDay(n)`가 `"D-62"`, `"D-day"`, `"D+3"`으로 만들어 줘요. |
| 6 | **출처 칩** | `SourceRef.label`을 그대로 보여주세요. `status === "추진 중"`이면 **주황 칩**이에요. 칩을 누르면 `openEventId` 카드를 열어요. `openEventId`가 없으면(어떤 카드와도 연결되지 않은 지침) 누를 수 없는 칩으로 보여주세요. |
| 7 | **AI 고지** | 챗봇 응답의 `disclaimer`("AI가 만든 답변이며 최종 판단은 담당자가 합니다")를 챗봇 창 아래에 항상 보여주세요. |

## 2. 화면별로 쓸 함수

모두 순수 함수라 브라우저 컴포넌트에서 바로 import해서 쓰면 돼요. 서버 호출은 필요 없어요.

```ts
import { events, eventsWithAdded, getTemplate, changes, guidelines } from "@/lib/data";
import { today, formatDDay } from "@/lib/dates";
import { buildDashboard, buildCalendar } from "@/lib/dashboard";
import { computeSchedule, unconfirmedAlerts } from "@/lib/schedule";
import { EMPTY_CLIENT_STATE, type ClientState } from "@/lib/types";

const state: ClientState = loadFromLocalStorage() ?? EMPTY_CLIENT_STATE;
const all = eventsWithAdded(state);           // 기본 행사 + 업로드로 추가한 행사

// 대시보드 위젯 4개
const d = buildDashboard(today(), state, all);
// d.upcoming[i].dDay / .nextStep?.label   → "2학년 수학여행 D-62, 다음 단계: 학생·학부모 의견 수렴 / 동의서"
// d.progress[i].percent                    → 행사별 진행률
// d.thisWeek                               → 이번 주 마감 단계
// d.overdue                                → 마감 지난 단계 (빨간색 추천)
// d.unconfirmedAlertCount                  → 변경 알림 건수

// 캘린더 (월 단위)
const items = buildCalendar("2027-05", today(), state, all);
// item.color: "green"(교내) | "blue"(교외), item.kind: "event"(행사일) | "deadline"(단계 마감), item.hasAlert → ⚠

// 행사 카드 상세 패널
const steps = computeSchedule(event, today(), state);
// steps[i]: { label, dueDate, daysLeft, state: "todo"|"done", overdue, alertIds }
const alerts = unconfirmedAlerts(event, state);   // 작년/올해 비교 박스에 쓸 변경 알림
```

### 카드 패널에서 상태를 바꾸는 법

| 사용자 동작 | 바꿀 곳 |
|---|---|
| 체크박스 | `state.stepStatus[eventId][stepId] = "done"` |
| 행사일 변경 | `state.eventDateOverrides[eventId] = "2027-05-19"` (마감일은 자동으로 다시 계산돼요) |
| 메모 추가 | `state.extraNotes[eventId].push({ year, note })` |
| "확인함" | `state.confirmedChangeIds.push(changeId)` |

바꾼 뒤 localStorage에 저장하고 다시 그리면 끝이에요.

### 표시 규칙 (기획서 그대로)

- **"우리 교육청 기준" 박스**: `event.officeRules`의 `consentRate`, `safetyStaff`, 출처 `sourceId`를 보여줘요.
- **전임자 메모**: `event.handoverNotes`와 `state.extraNotes`를 노란 메모지 모양으로 보여줘요.
- **변경 알림 비교 박스**: `before` → `after`. `status === "추진 중"`이면 주황 배지와 **"현행 기준은 그대로"** 문구를 함께 보여줘요.
- 카드 아래에 `updatedBy`·`updatedAt`으로 "누가 언제 수정"을 표시해요.

## 3. 챗봇 API — `POST /api/chat`

```ts
const res = await fetch("/api/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    question: "동의율은 몇 % 넘어야 해?",
    focusEventId: "E-07",   // 선택: 지금 열려 있는 카드
    state,                  // 선택: 보내면 체크 상태·바뀐 행사일을 반영해서 답해요
  }),
});
const data: ChatResponse = await res.json();
```

응답 예시:

```json
{
  "answer": "인천광역시교육청 기준으로, 숙박형 수학여행은 학년 전체 학부모의 80% 이상이 ...",
  "sources": [
    { "id": "G-INC-01", "kind": "guideline", "label": "인천광역시교육청 2026 현장체험학습 매뉴얼 G-INC-01 · 2026 기준", "status": "시행", "baseDate": "2026-03-01", "openEventId": "E-07" },
    { "id": "E-07", "kind": "event", "label": "행사카드 E-07 · 2학년 수학여행 (숙박형) · 2026 전임자 메모", "openEventId": "E-07" }
  ],
  "notFound": false,
  "mode": "llm",
  "disclaimer": "AI가 만든 답변이며 최종 판단은 담당자가 합니다."
}
```

- 답변을 기다리는 동안 캐릭터의 **"생각 중"(점 3개) 모션**을 보여주세요. 보통 1~2초 걸려요. AI 서버가 느리면 최대 20초까지 기다린 뒤 고정 답이 와요.
- `mode`는 `"llm"`(실제 AI), `"demo"`(고정 답), `"fallback"`(AI 오류로 고정 답), `"blocked"`(개인정보 질문 차단) 중 하나예요. 화면에 꼭 보여줄 필요는 없지만 발표 리허설 때 디버깅용으로 작게 띄워 두면 편해요.
- HTTP 400은 질문이 비었거나 500자를 넘었다는 뜻이에요. 이때 `{ error }` 메시지를 보여주세요.
- 개인정보 차단, "찾지 못했어요", 법적 판단 고정 문구, "추진 중" 문구는 **서버가 알아서 붙여요.** 프론트는 `answer`를 줄바꿈(`\n`)만 살려서 그대로 보여주면 돼요.

## 4. 결과보고서 업로드 (P1) — 2단계

```ts
// 1단계: 파일 → 마스킹 미리보기
const fd = new FormData();
fd.append("file", file);                      // .pdf 또는 .txt, 4MB 이하
const r1 = await fetch("/api/upload/extract", { method: "POST", body: fd }).then(r => r.json());
// r1: { fileName, charCount, maskedText, maskCount, hits: [{kind:"name",count:3}, ...] }  또는 { error }

// → 화면에 maskedText 미리보기 + "이름 3개, 전화번호 1개를 가렸어요"를 보여주고, 사용자가 확인을 누르면:

// 2단계: 마스킹 텍스트 → 행사 카드 초안
const r2 = await fetch("/api/upload/draft", {
  method: "POST", headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ maskedText: r1.maskedText }),
}).then(r => r.json());
// r2: { draft: EventDraft, mode }

// 3단계: 사용자가 초안을 고치고 "저장"을 누르면
import { draftToEventCard } from "@/lib/upload/draft";
const card = draftToEventCard(editedDraft, { id: `U-${Date.now()}`, nextEventDate: "2028-05-10", year: 2027 });
state.addedEvents.push(card);   // → 캘린더·대시보드에 자동으로 나타나요
```

- **미리보기 화면은 꼭 넣어 주세요.** 이름 마스킹은 정규식이라 100% 잡지 못해요. 사람이 확인하는 단계가 보안 설계의 일부예요.
- 원본 파일은 서버에 저장하지 않아요. 프론트도 localStorage에 원문을 넣지 말아 주세요.

## 5. 프론트에서 하면 안 되는 것

- `lib/chat/llm.ts`, `lib/env.ts`, `lib/upload/extract.ts`를 import하지 마세요. 서버 전용이라 import하면 빌드 에러가 나요(일부러 그렇게 막아 뒀어요).
- 환경변수 이름에 `NEXT_PUBLIC_`을 붙여서 API 키를 넣지 마세요.
- 메모 입력란에 학생 이름을 넣지 않도록 placeholder로 안내해 주세요. 예: "학생 이름·연락처는 적지 마세요".

## 6. 바로 확인할 수 있는 곳

- `npm run dev`로 서버를 띄우고 `http://localhost:3000/api/health`를 열면 서버 상태, 데모 모드 여부, 데이터 오류를 볼 수 있어요.

## 7. 프론트가 정해서 백엔드에 알려줄 것

- **화면에 필요한데 위 함수에 없는 값.** 말해 주면 `lib/`에 추가할게요. 직접 계산하면 화면마다 숫자가 달라질 수 있어요.
- **데이터 글자 수정.** 행사명·단계 이름 같은 글자를 바꾸고 싶으면 `data/*.json`을 고친 뒤 `npm test`를 실행해요. id 연결이 깨지면 테스트가 알려줘요.
- **캐릭터 말풍선 문구.** 기획서 데모 시나리오의 "수학여행 D-62예요!"처럼 캐릭터가 먼저 말하는 문장은 `buildDashboard().upcoming[0]`으로 만들면 돼요. 다른 문장이 필요하면 알려 주세요.
- **챗봇 추천 질문 버튼.** 넣는다면 데모 고정 답이 있는 4개를 추천해요. 그래야 인터넷이 끊겨도 안전해요.
  - "동의율은 몇 % 넘어야 해?"
  - "안전요원 몇 명 있어야 해?"
  - "사고 나면 교사 책임은?"
  - "진로활동 특기사항 몇 자까지야?"
